## 一、需求回溯与原版设定对齐

| 原版设定 | 实现位置 | 状态 |

## 二、核心概念与术语

| 术语 | 定义 |
|---|---|
| 灵力（Spirit Power） | 玩家专属资源，百分制，范围 `[0, maxSpirit]`，默认上限 100 |
| 灵珠（Spirit Bead） | 消耗品物品，五品质，吸收后按比例回复灵力 |
| 灵珠掉落（Bead Drop） | 怪物死亡时就地生成的一颗灵珠掉落物，立刻可捡（2026-10-02 起） |
| 尸体（Corpse） | 只剩末影龙在用：原地生成的倒地实体 + 紫色光柱地标 |
| 搜刮（Loot） | 玩家右键末影龙尸体，内部全部灵珠一次性进入背包 |

## 二·补、灵珠命名、图标与来源维度

### 命名：`<怪物名>灵珠`

**物品名 = `<怪物名>灵珠`**（品质不进名字），例如：

```
僵尸灵珠        骷髅灵珠        蜘蛛灵珠
恶魂灵珠        末影龙灵珠
```

名字是动态拼的，不是写死的翻译：重写了 `SpiritBeadItem#getName`，
从物品 NBT 的 `Source` 字段取出怪物 ID，再走原版 `entity.<namespace>.<path>`
语言键拿到本地化名。所以加任何怪物（含模组怪物）都不用改语言文件。

**品质移到 tooltip 副栏**（`tooltip.wulingdiguo.bead_quality`，数值按品质上色）：

```
僵尸灵珠
品质：极品          ← 金色
吸收可回复 20% 灵力   ← 按「僵尸 × 极品」算，见第五节
Shift + 右键 吸收
```

没有来源（比如从创造物品栏直接拿出来的）退化为 `<品质>灵珠`。

### 图标：一种怪物一张图（不按品质分）

- **33 只怪物**各有一张 16×16 灵珠图标，放在
  `assets/wulingdiguo/textures/item/bead/<怪物>.png`；
- **颜色严格取自该怪物自己的实体贴图**（`client-extra.jar` 的
  `assets/minecraft/textures/entity/**.png`），规则是：
  - **球体主色** = 该贴图去掉最暗的 15% 像素（轮廓、阴影）后的平均色 ——
    也就是这只怪在游戏里给人的整体印象色：僵尸是绿的、烈焰人是金的、
    岩浆怪是橙红的、女巫是紫的、骷髅是灰白的；
  - **灵核色** = 贴图里最鲜艳的常见色（僵尸的青色衬衫、末影人的末影紫、
    骷髅的骨黄）；贴图本身没有彩色的（末影人 / 凋灵 / 末影龙）
    用人工指定的特征色。**颜色不做色相偏移**，怪物什么色就是什么色；
  - 只做两处兜底：太暗的（末影人、监守者）把明度抬到看得清，
    灵核与球体太接近时把灵核推暗/推亮一档（否则 16×16 上灵核会糊掉）；
- 画法是**硬像素分层**（4 档明暗 + 最外圈深色描边 + 左上高光 + 中心菱形灵核），
  不用连续渐变，所以放大后依然是清晰的像素块，不会糊成一团；
- 贴图格式必须是 **16×16 RGBA（PNG colortype 6）**：球体以外的像素 alpha=0，
  **背景全透明**，否则游戏里会出现一个黑方块垫在灵珠后面
  （脚本第一版正是栽在这里 —— 写 PNG 时只写了 RGB 三通道，alpha 被丢掉、
  透明区变成纯黑。`_png_blob()` 现在按像素是否带 alpha 自动选 colortype）；
- 选图机制：基模型 `spirit_bead_<品质>.json` 里列一份
  `{predicate:{custom_model_data:N}} → models/item/bead/<怪物>.json` 的覆盖表，
  服务端生成灵珠时按 `Source` 往 NBT 写 `CustomModelData = N`
  （索引表见 `SpiritBeadItem.applyModel` / `BeadModels`）；
- 没有专属图的来源（例如其它模组的怪物）**不写** `CustomModelData`，
  模型自动退回原来那张品质图（凡品~极品五张仍在，颜色区分品质）。
- **已退役的怪物不留图、只留空号**：蠹虫（`silverfish`，23 号）、
  末影螨（`endermite`，8 号）、恼鬼（`vex`，27 号）2026-09-26 起
  彻底退出灵珠体系 —— 既不出灵珠、也不生成图标。
  它们在序号表里占的号仍然空着 ——
  因为 `CustomModelData` 是写进灵珠 NBT 的，序号一旦整体前移，
  **已刷出的灵珠会全部串图**。所以退役只删图与模型，不动别人的号
  （脚本里的 `RETIRED` 元组，把怪物名加进去再跑一次即可）。

重新生成全部图标：

```bash
python tools/gen_bead_textures.py
```

产出：33 张贴图 + 33 个模型 + `BeadModels.java`（36 条，含 3 个退役空号）
+ 5 个品质基模型的覆盖表，
外加两张验收用图 `docs/bead_icons_preview.png`（总览）与
`docs/bead_preview.html`（放大的验收页，带中英文名与色号，直接在浏览器里看）。

脚本里另有一个备选画法 `render_bead_texture()`：把怪物贴图直接嵌进珠心。
当前采用的是「球体 + 灵核」，想换风格改 `main()` 里那一行即可。
**不要手改生成出来的贴图/模型/索引表**。

## 三、掉落流程（状态机）

```
怪物被判定为 Enemy
        │
        ▼
  LivingDeathEvent 触发
        │
        ├─ 位于客户端？ ── 是 ─→ 直接返回
        ├─ 不在 Enemy 体系？ ── 是 ─→ 直接返回
        ├─ 命中排除名单？ ── 是 ─→ 直接返回
        │                  （默认：minecraft:silverfish、minecraft:vex）
        ▼
  SpiritBeadDrops.roll(dead)          ← 掷 1 颗灵珠（品质由怪物强度决定）
        ├─ SpiritBeadDrops.dropAt     ← 就地掉在地上，立刻可捡（2026-10-02 起）
        │     └─ 末影龙例外：仍走 CorpseEntity.create（专属尸体 + 光柱地标）
        ▼
  level.addFreshEntity(item)
```

**末影龙那条路**（保留的旧流程）：

```
  CorpseEntity.create(level, dead)
        ├─ captureAppearance：剔除无用 NBT 字段，只留外观数据
        ├─ 位置/朝向继承死者，水平速度继承 20%
        ├─ fillBeads：恒定 1 颗极品灵珠（来源 = minecraft:ender_dragon）
        ▼
  level.addFreshEntity(corpse)
        │
        ▼
  ┌──── 尸体生命周期（只剩末影龙） ────┐
  │ 每 tick 重力下落                    │
  │ 玩家右键 → 搜刮                     │──→ 灵珠入背包 → 尸体保留（光柱地标）
  │ 超时 12000 tick                     │──→ 灵珠掉地上（可关）→ 尸体 discard
  └────────────────────────────────────┘
```

**排除机制**：分两层，取并集。

1. **硬名单 `Config.NEVER_DROPS`**（代码里写死，玩家改不动）：
   蠹虫、恼鬼 —— 原版设定点名排除；末影螨 —— 2026-09-26 追加。
   三者同时也都从图标体系退役（见上一节的 `RETIRED`）。
   这几只是设定层面就不该有灵珠的，钉在代码里才能保证任何存档、任何配置下都不掉。
2. **配置项 `drop.excludedMobs`**（生物 ID 字符串列表，默认同上）。
   给玩家留的扩展口子，加模组怪物也能直接排除。

> ⚠️ 为什么要两层：Forge 的配置文件**一旦生成就固定**在 `config/` 目录里，
> 之后再改代码里的默认值对旧配置**完全无效**。只靠配置项会出现
> 「代码里明明排除了，进游戏还掉灵珠」的假象，所以设定性的排除一律写进硬名单。

## 四、品质算法

### 4.1 掉落数量

**一个怪物 = 一颗灵珠，恒定值，不随任何因素影响。**

怪物实力差异只体现在**品质**上，不体现在数量上。
这是原版设定明确要求的规则，因此代码中不存在数量相关的随机，也没有留配置开关。

> 数据模型里尸体仍然持有 `List<ItemStack>`，是为了容纳未来的例外情况
> （例如 BOSS 额外掉落）。常规流程下这个列表长度恒为 1。
> 2026-10-02 起普通怪不再生成尸体，这条说明只剩末影龙那条路还成立。

### 4.2 品质权重

```
base      = max(0.05, 1 + (怪物最大生命 - 20) / 40 * strengthInfluence)
weight(i) = 基础权重(i) * base ^ i           // i = 品质序号：凡0 良1 优2 上3 极4
```

默认基础权重：`凡 50 / 良 30 / 优 14 / 上 5 / 极 1`

由此得到的实际掉落概率（20HP 常规怪物，`strengthInfluence = 1` 时 `base = 1.0`）：

| 品质 | 权重 | 概率 |
|---|---|---|
| 凡品 | 50 | 50.0% |
| 良品 | 30 | 30.0% |
| 优品 | 14 | 14.0% |
| 上品 | 5 | 5.0% |
| 极品 | 1 | 1.0% |

高血量怪物（如铁傀儡 100HP，`base = 3.0`）会把高品权重指数级放大：

| 品质 | 权重 | 概率 |
|---|---|---|
| 凡品 | 50 | 8.3% |
| 良品 | 90 | 15.0% |
| 优品 | 126 | 21.0% |
| 上品 | 135 | 22.5% |
| 极品 | 81 | 33.2% |

> 想把掉落改成纯随机、与怪物强度无关，把 `strengthInfluence` 设为 0 即可。
> 想提高整体稀有度，直接调 `weightJi` 等基础权重。

### 4.3 回复量：怪物基准 × 品质倍率

吸一颗灵珠回多少灵力，**同时取决于它来自哪只怪、以及是什么品质**：

```
回复量(%) = 怪物基准(来源) × 品质倍率(品质)
```

| 品质 | 凡品 | 良品 | 优品 | 上品 | 极品 |
|---|---|---|---|---|---|
| 倍率 | ×1.0 | ×1.5 | ×2.0 | ×3.0 | ×4.0 |

**怪物基准** = 该怪物「凡品」灵珠的回复量，写在 `item/BeadPower` 的 `BASE` 表里，
按怪物强弱分四档：

| 档次 | 基准 | 怪物 |
|---|---|---|
| 弱小 | 4 ~ 6 | 史莱姆 / 僵尸村民 / 僵尸 / 骷髅 / 尸壳 / 猪灵 / 僵尸猪灵 5，流浪者 / 溺尸 5.5，苦力怕 / 恶魂 / 幻翼 6 |
| 普通 | 7 ~ 10 | 掠夺者 / 守卫者 7，女巫 / 烈焰人 / 凋灵骷髅 / 卫道士 8，末影人 / 疣猪兽 / 潜影贝 9，僵尸疣猪兽 10 |
| 精英 | 12 ~ 17 | 唤魔者 / 幻术师 12，猪灵蛮兵 13，远古守卫者 15，劫掠兽 17 |
| 首领 | 22 ~ 25 | 巨人 22，末影龙 / 凋灵 / 监守者 25 |

两个锚点：**僵尸凡品 5%**、**末影龙极品 100%**（基准 25 × 倍率 4）。完整 33 只怪的
对照表见 `docs/bead_power.html`。

**表外的来源**（其它模组的怪）不会变成「回 0%」：按最大生命值兜底 ——
20 血 = 5%，每多 1 点血 +1/9，钳制在 `[3, 25]`。生命值取不到（非生物 / 未注册 ID）
则退回 `DEFAULT_BASE = 5`。

**改数值**：改 `tools/gen_bead_textures.py` 里的 `MOB_RESTORE` 字典，重跑脚本 ——
`BeadPower.java` 与验收表会一起更新。品质倍率在 `Config` 里（`restoreMultiplierFan..Ji`），
玩家可直接改配置。注意：**旧版的 `restoreFan..restoreJi` 是绝对百分比，已废弃**，
新键是 `restoreMultiplierFan..Ji`（旧配置文件里的旧键会被 Forge 忽略，不会误读成倍率）。

## 五、灵力面板与回复

### 5.1 数值定义

- 上限 `maxSpirit`，默认 **100**
- 自然回复：`regenPerMinute` **1.0% / 分钟**
- 1 分钟 = 1200 tick → 每 tick 回复 `1 / 1200 ≈ 0.000833`

### 5.2 实现要点

每 tick 的回复量小于 `float` 精度累加的误差上限，直接累加会在满值附近抖动甚至停滞。
`SpiritPowerImpl` 用一个 `carry` 累加器攒够 `0.005` 再一次性入账，规避这个问题。

```
tick():
  if spirit >= max: spirit = max; return
  carry += regenPerMinute / 1200
  if carry >= 0.005:
      spirit += carry
      carry = 0
```

数值存储使用 `float`（单位：百分比点数），读写均夹紧到 `[0, max]`。

### 5.3 面板同步

服务端是数据权威。同步时机：

| 时机 | 处理方式 |
|---|---|
| 常规 | 每 5 tick 推送一次 `SpiritPowerSyncPacket` |
| 玩家登录 | `PlayerEvent.PlayerLoggedInEvent` |
| 切换维度 | `PlayerEvent.PlayerChangedDimensionEvent` |
| 死亡/重生 | `PlayerEvent.Clone` 直接搬运 NBT 数据 |
| 指令改动 | 变更后立即推送 |

客户端将值缓存于 `ClientSpiritData`，供 HUD 读取。

## 六、交互规则

### 6.1 吸收灵珠（Shift + 右键）

```
条件：按住 Shift 且不是客户端侧执行
 ├ 未满灵力 → spirit += 回复量(来源怪, 品质) → 物品 -1 → 音效 + 提示
 └ 已满灵力 → 提示「灵力已满」→ 不消耗物品
```

未按 Shift 的右键**完全不触发**，避免误操作。

### 6.2 尸体掉落（2026-10-02 起）

普通怪不再留尸体，灵珠**直接掉在地上**：

```
条件：敌对生物死亡、不在排除名单
 → 死亡处生成 1 颗灵珠掉落物（立刻可捡，无拾取延迟）
 → 玩家走过去自动捡起（原版拾取逻辑）
```

> 以前是「留一具倒地尸体 → 右键搜刮 → 灵珠入背包」，现在少了一步。
> 立刻可捡是用户 2026-10-02 的选择，手感接近原来的右键取珠。

### 6.3 搜刮尸体（右键，只剩末影龙）

```
条件：目标是 CorpseEntity 且尸体仍有灵珠
 → 逐颗入背包
 → 背包已满的部分掉落到地面
 → 提示「获得 N 颗灵珠」
 → 末影龙尸体保留（光柱地标继续存在）
```

## 七、尸体渲染方案（只剩末影龙）

不自己建模，而是**复用原版渲染器渲染还原出的怪物模型**，再整体放倒成仰面躺地姿态。
好处是：任何怪物（含后续可能加入的自定义生物）都自动获得正确的尸体外观。
2026-10-02 起普通怪不再生成尸体，这一段只剩末影龙在用（它的尸体还额外带紫色光柱）。

### 7.1 数据通路

```
服务端 saveWithoutId(死亡怪物)       剔除 Pos/Motion/Health/Attributes 等无关字段
        ↓  PlayerEvent.StartTracking 时随 CorpseDataPacket 下发
客户端 EntityType.loadEntityRecursive(NBT)   还原出一个不加入世界的实体
        ↓
CorpseRenderer 调用该实体对应的原版 EntityRenderer
```

### 7.2 姿态矩阵推导

`LivingEntityRenderer` 渲染时朝向取自 `yBodyRot`，而不是 `render()` 传入的 yaw 参数
（这点很容易踩坑），所以：

1. `getOrCreateDisplay()` 把 `yBodyRot / yHeadRot / yRot` 全部归零
   → 原版渲染器输出的恒为「直立、脚在原点、面朝南」的模型。
   记模型三轴：up = (0,1,0)、forward = (0,0,1)、side = (-1,0,0)
2. 目标姿态：头朝怪物死亡时的朝向 `h(θ) = (-sinθ, 0, cosθ)`，仰面朝天
   → 即 up → h、forward → (0,1,0)
3. 满足条件的旋转可分解为 `P = Ry(180° - θ) · Rx(-90°)`；
   PoseStack 的 `mulPose` 由外向内叠加，所以**调用顺序必须是先 Y 后 X**
4. 旋转围绕实体原点（脚底高度）发生，身体厚度会以原点为中心上下各半，
   因此在世界坐标系下先抬高 `HEIGHT_OFFSET` 贴地

> `HEIGHT_OFFSET`、`SCALE` 在 `CorpseRenderer` 顶部，观感需要微调时改这两个常量。

## 八、配置项清单

位于服务端生成的 `config/wulingdiguo-common.toml`。

| 分组 | 键 | 默认 | 说明 |
|---|---|---|---|
| spirit | maxSpirit | 100.0 | 灵力上限 |
| spirit | regenPerMinute | 1.0 | 每分钟自然回复百分比 |
| bead | restoreMultiplierFan ~ Ji | 1.0 / 1.5 / 2.0 / 3.0 / 4.0 | 各品质回复倍率（× 怪物基准） |
| drop | weightFan~weightJi | 50/30/14/5/1 | 各品质基础权重 |
| drop | strengthInfluence | 1.0 | 怪物强度对品质的影响系数 |

| corpse | lifetimeTicks | 12000 | 尸体存在时长（100 分钟；2026-10-02 起只对末影龙尸体生效） |
| corpse | dropBeadsOnTimeout | true | 超时后是否把灵珠掉地上（同上，只对末影龙） |

## 九、网络与代码地图

| 包 | 类 | 职责 |
|---|---|---|

## 十、开放项（需要后续设定补充）

以下问题在现有文档中未定义，目前按保守方案实现，**后续部分发来后建议回头调整**：

1. **灵力的用途**：目前只有面板与吸收，没有消耗接口。技能/功法系统接入时可直接调
   `ISpiritPower#addSpirit(负值)`，建议届时增加「灵力不足时拒绝施放」的统一校验开关。
2. **灵珠的其他获取途径**：目前仅怪物掉落。玩家之间的交易、商店、任务奖励都没做。
3. **掉落物是否区分「谁打死的」**：现在只要怪死了就掉，任何玩家都能捡。
   多人服里若想「只给击杀者」，在 `SpiritBeadDrops.dropAt` 前加一层判定即可。
4. **死亡是否损失灵力**：当前 `PlayerEvent.Clone` 无条件继承，即死亡不掉灵力。
   若设定是「死亡掉一半」，在这里把 `min / max` 处理加上即可。
5. **品质是否受抢夺附魔影响**：当前未接入 `Looting` 等级。想要的话在 `SpiritBeadDrops#randomQuality` 里加成即可
   （注意：只能加品质，不能加数量 —— 数量被设定锁死为 1）。
6. **BOSS 类怪物**：末影龙已单独处理（保留尸体 + 固定极品灵珠）；
   凋灵等其他 BOSS 目前与普通怪一样直接掉灵珠，若设定上要特殊处理需再加分支。
