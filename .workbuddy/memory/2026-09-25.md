# 2026-09-25

## 《武灵帝国》0.2.5：突破物资分批缴纳 + 灵珠命名去括号

### 用户口径
- **突破物资可以先提交一部分**（后期突破要十几二十组，背包放不下）
- **灵珠名称 = `<品质><怪物名>灵珠`**（去掉原来的括号），例：`极品僵尸灵珠`

### 实现
1. 灵珠名：`item.wulingdiguo.spirit_bead_named` 由 `%1$s(%2$s)灵珠` 改为 `%1$s%2$s灵珠`
   （en_us 改 `%1$s %2$s Bead`）；`SpiritBeadItem#getName` 逻辑未动，纯语言键改动。
   docs/灵珠系统设计规格.md 第二·补节同步更新。
2. **缴纳池**：`WuLingData` 新增 `Submit`(CompoundTag) + `SubmitTarget`(int)，
   键格式 `item|<物品ID>` / `bead|<怪物来源ID>`；`unbind()` 会清池（调用方先退还）。
3. `BreakthroughRequirement` 重写：
   - `evaluate(player, target, pool)` → `Row(name, need, have, deposited, ok)`，
     have = 背包 + 池子（上限 need），额外给出 deposited 供面板显示「已缴 N」
   - `submitPartial(ServerPlayer, target, data)` 分批缴纳，只缴到需求上限；
     目标境界变化时先 `refundAll` 再重开
   - `isPoolComplete` / `tryConsumeAndAdvance`（先自动补缴背包剩余，再判池子齐全 → 清池）
   - `refundAll`：池子里的东西原物退还（`item|` → 物品；`bead|` → 极品灵珠 + Source NBT），
     放不下的掉在脚下。`/wuling spirit unbind` 已改为先退还再解绑
4. 新增 `WuLingSubmitPacket`（包 ID 5，C→S），`WuLingSyncPacket` 增加缴纳池负载，
   `ClientWuLingData.submitted()` 缓存；`WuLingUpgradeScreen` 面板 240×200，
   底部两个按钮「提交物资」「突破」，行名后灰色「已缴 N」，并加提示行。
5. 版本 0.2.5，`BUILD SUCCESSFUL in 1m 18s`，产物 `build/libs/wulingdiguo-0.2.5.jar`（120,642 B）。
   已解包核对：WuLingSubmitPacket.class、新语言键、mods.toml version="0.2.5" 均在。

### 构建环境事故（重要，已记入 MEMORY.md）
项目从 Administrator 账户迁到 jiami 账户后首次构建报
`Could not apply requested plugin [id: 'net.minecraftforge.gradle'] ... Plugin ... not found`，
根因是 `_env/ghome/caches/modules-2/files-2.1/` 下 **3 个 jar 被写成全零字节**：
ForgeGradle-6.0.54、commons-compress-1.18、netty-handler-4.1.82.Final。
`_env/ghome2` 里有完好副本，覆盖后构建恢复正常。另：命令前加
`JAVA_TOOL_OPTIONS="-Dfile.encoding=UTF-8 -Dsun.jnu.encoding=UTF-8"`，否则日志里中文路径显示为乱码。
