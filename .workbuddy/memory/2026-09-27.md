## 《武灵帝国》0.2.20：武灵升级面板改为 Shift + N 打开，且不需要绑定器

   「右键 / Shift+N：武灵面板（不需要绑定器）　Shift+M：凝聚出实体武灵（消耗灵力）」。
6. 绑定（选种类）**仍然需要绑定器**，一行没动。

### ⚠️ 顺手修掉一个潜伏的编码地雷：en_us.json 坏字节
改文案时 Edit 工具反复报「String to replace not found」，明明 `grep -n` 能看到该行。
排查发现 **`en_us.json` 不是合法 UTF-8**：文件里有 **4 处 `e2 86 3f`**，
本该是「→」的 `e2 86 92`，第三个字节被写成了 ASCII 的 `3f`（`?`）——
典型的「UTF-8 文本被 GBK 环境工具处理过」的痕迹。
- 症状链：Python 按 utf-8 读该文件直接抛 `UnicodeDecodeError` → Edit 工具也匹配不上 → 改不动文案。
- 修复：`b.replace(b'\xe2\x86\x3f', '→'.encode('utf-8'))`，4 处全修，`json.load` 通过（108 键）。
- 顺带核对：**中文 lang 一直干净**（用的是 →，方向也对），英文那 4 处按中文语义统一成 →。
- 检查手法：`python -c "open(p,'rb').read().decode('utf-8')"`；
  或按行逐行 decode 定位坏行。**PNG 报同样的错是正常的（二进制文件）**，只看文本文件。
- 教训：**以后改 lang 文件优先用 Python 读写**（`encoding='utf-8'`），比 Edit 工具更抗坏字节。

## 0.2.21 —— 村民牧师抽取开启武灵 + 怪物等级系统

### 需求原文
> 「给村民牧师加入武灵开启的技能（是抽取而不是选择）；加入怪物等级系统（用木 → 石 → 黄金 →
> 玄铁 → 钻石 → 下界合金 → 绿宝石）攻击都用本属性的剑做攻击，每种怪物都有小概率有属性，
> 但怪物的等级越高约非常稀有！」

### 一、村民牧师：抽取开启武灵（`WuLingBinding#openByNpc`）

- 触发 = **手持灵珠右键村民牧师**（职业 `VillagerProfession.CLERIC`）。空手右键仍是原版交易。
- **判定「是否接管这次交互」的窍门**：手里拿着灵珠才接管（`openByNpc` 返回 true →
  `event.setCanceled(true)`，交易界面不会盖上来）；没拿灵珠返回 false 完全不干涉。
  这样既不破坏牧师交易，又让「递珠子」这个动作有独占语义。
- 种类走 `WuLingType.roll`（不是 `byKey`）＝**抽取**；品质上限仍由交出去的灵珠决定。
- **绑定器是「仅限创造模式取得」，所以这条才是生存玩家的唯一开启途径** —— 已写进文档，
  别再想着「生存怎么选种类」。
- 表现：附魔台音效 + `VILLAGER_YES`/`VILLAGER_NO` + `PLAYER_LEVELUP` +
  `ParticleTypes.ENCHANT`（符文）/ `HAPPY_VILLAGER`（成功）/ `ANGRY_VILLAGER`（拒绝）。

### 二、怪物等级（`wuling/MonsterTier.java`）

- **口径理解：我按「等级 = 属性」落地** ——「木属性」就是「木阶」，攻击用该阶的剑。
  若原意是两维度（等级 + 剑/斧/水/火 种类），再加一层即可，文档「开放项 6」写了。
- 阶梯直接复用 `WuLingRealm` 七档；`swordOf` 映到木/石/金/铁/钻石/下界合金剑 +
  本模组的 `ModItems.EMERALD_SWORD`。
- 概率：`tierChance`（默认 0.10，0 = 关闭）× 几何衰减 `tierRarityRatio`（默认 2.5，
  权重 = 1 / ratio^阶数）→ 绿宝石阶约占全部怪物 **1/4000**。
- 血量：倍率 = 1 + 大境界序号 × `tierHealthBonusPerRealm`（默认 0.5，木 1.0 → 绿宝石 4.0）。
- 排除名单 14 项（`tierExcludedMobs`）：不近战的（苦力怕/史莱姆/岩浆怪/恶魂/烈焰人/女巫/潜影贝）
  + 不渲染手持物或另有攻击方式的（幻翼/守卫者/远古守卫者/蠹虫/末影螨/凋灵/末影龙）。
- 三个关键实现点：
  1. **等级只掷一次** → 结果写进 `Entity#getPersistentData()`（Forge 的 `ForgeData`，
     会随实体存档），区块卸载再加载不重掷、不刷新手气。
  2. **血量加成走固定 UUID 的属性修饰符**（`6f3a5e2c-9f41-3c62-93d5-6f1b6f5b0a31`），
     每次进世界 `removeModifier` 再 `addPermanentModifier` → **永远不会叠血**；
     补满血只在第一次（`KEY_HEALTH` 标记）做，重载不会白送一次满血。
  3. **主手掉落率钉成 0**（`Mob#setDropChance(MAINHAND, 0.0F)`）——
     否则刷出一柄绿宝石剑就等于绕开整条武灵晋升线。
     （已 javap 过 `Mob#dropCustomDeathLoot`：判定是 `random.nextFloat() - looting*0.01F < dropChance`，
     所以 0 的时候带抢夺 III 仍有约 3% 兜底，量级可忽略。）
- **伤害不用自己写**：`Mob#setItemSlot(MAINHAND, 剑)` 之后，剑的属性修饰符由原版
  `LivingEntity#handleEquipmentChanges` 自动生效 —— 与玩家侧强化同一套机制。
- **隐性联动**：灵珠品质按来源怪最大生命值推算，所以高阶怪掉的珠子天然更好。
- 击杀提示：`LivingDeathEvent` 里读 `MonsterTier.tierOf(dead)`，报给击杀者
  「击杀了一头 钻石阶 妖兽」。

## 0.2.24 —— 支持 1.20.1 全部 Forge 版本（19:2x~19:5x）

用户：「能不能支持 1.20.1 所有版本的 forge」。查清后发现问题**比想象严重**。

### 版本谱系（拉 maven-metadata 得到）
1.20.1 的 Forge 共 **132 个版本**：47.0.0 ~ 47.4.23（推荐 47.4.10）。

### 三处不兼容（都是「新版有、老版没有」）
① **主类构造函数必须无参**（最大问题）
   - 47.0.0 的 `FMLModContainer#constructMod()` = `modClass.getDeclaredConstructor().newInstance()`，
     只认无参构造函数；`47.3.10` 起才有「注入 `FMLJavaModLoadingContext`」，
     实现是「先试带参、NoSuchMethodException 再退回无参」。
   - 本项目原用 `WulingEmpire(FMLJavaModLoadingContext context)` → 在 **132 个中的 89 个**
     （47.0.x 23 + 47.1.x 38 + 47.2.x 20 + 47.3.0~47.3.7 8）上加载失败。
   - 改：`public WulingEmpire()` + `FMLJavaModLoadingContext.get()`。
② **配置注册**：47.0.0 的 `FMLJavaModLoadingContext` 是独立类（不继承 `ModLoadingContext`），
   没有 `registerConfig`。改回 `ModLoadingContext.get().registerConfig(...)`（两版都在）。
③ **`ResourceLocation.fromNamespaceAndPath` 等是后期 backport**：47.0.0 的 patched MC 里没有。
   共 4 处 → 全改两参构造函数 `new ResourceLocation(ns, path)`：
   `WulingEmpire.id` / `ModCapabilities`（两个**静态字段**，旧版会在类加载时直接 NoSuchMethodError）/
   `SpiritQuality.itemTexture` / `WuLingType.id`。`tryParse` 两版都有，未动。

### 做法与验证
- `gradle.properties`：`forge_version` 47.4.23 → **47.0.0**（编译目标 = 最低支持版；

## 0.2.26 —— 改为「总倍数」，每档碾压上一档（20:2x）

用户否掉 0.2.25 的系数（木2 石2.5 黄金5 玄铁5.5 钻6 下界7 绿宝石10）：「不，每个级别都碾压上一个级别」。
复盘：后段相邻比只有 1.26~1.31，阶梯太平；且黄金倒挂只是被补偿到「勉强不低于石」。

### 改法：语义从「追加系数」换成「总倍数」
- `WuLingRealm`：字段/方法 `manifestScale` → **`manifestMultiplier`**，
  值 = 木 **3** / 石 **4** / 黄金 **8** / 玄铁 **9** / 钻石 **11** / 下界合金 **14** / 绿宝石 **15**。
- `WuLingType#empower`：`addPct = multiplier - 1`，再乘配置百分比；
  `amplify(...)` **新增 `referenceOffset` 参数** —— 攻击力传 **1.0**（玩家基础攻击力，
  原版「木剑 4」= 修正值 3 + 这 1 点），护甲/韧性传 **0.0**。
  这样「**最终显示值 = 原版显示值 × 倍数**」严格成立，不再差 1 点。
- 剑最终（配置 100%）：4→**12** → 20 → 32 → 54 → 77 → 112 → **240**（+锋利V≈243）。
  相邻倍率 1.67 / 1.60 / 1.69 / 1.43 / 1.45 / **2.14** —— **全部 ≥1.43 倍**。
- 绿宝石档：剑 243（含附魔）· 斧 **270** · 镐 210 · 铲 217.5 · 胸甲 护甲 **240** / 韧性 **180**。
  → 一击秒杀满血末影龙（200 血）已达成且有余量（第五部预留位）。

### 为什么倍数不是等比的（这轮想清楚了，写进注释与文档）
原版各材质底子**不等差**：剑伤害 木4 石5 **金4（比石还低）** 玄铁6 钻7 下界8，绿宝石是独立物品 16。
要让**实际数值**成阶梯，倍数必须按底子补偿 —— 黄金档必须给到 8 才不倒挂。
（金甲原版韧性 0 → 黄金档仍只有护甲加成。）
