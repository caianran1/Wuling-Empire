## 《武灵帝国》0.2.7：灵珠图标重画（用户反馈「太粗糙」→ 按怪物颜色重做）

### 用户口径
- 上一版图标「太粗糙」，要求**按怪物的颜色做**
- 给出 A/B 两种画法后，用户选定 **A：球体 + 菱形灵核**（16×16，不上 32×32）

### 上一版为什么会「糙」（根因，别再犯）
1. **颜色被"归一化"改歪**：为了让主色够亮够艳，脚本强加饱和度下限
   （`s=max(s,0.35)`、`v=max(v,0.42)`），把末影人/凋灵的黑紫拉成棕灰；
2. **为了"36 张不重样"乱调色相**（`unique_accent` 按哈希漂 hue），
   结果僵尸变亮绿、骷髅变淡青、女巫变褐；
3. **画法是连续渐变**（`light` 浮点插值）+ 一大块四角星色斑 → 16×16 上糊成一团。

### 新版做法（现行口径）
- **球体主色 = 贴图去掉最暗 15% 像素后的平均色**，只做「亮到看得见」的兜底，
  **绝不动色相**；实测结果与视觉印象一致：
  僵尸 #58963C 绿、女巫 #7A42B0 紫、岩浆怪 #B03E12 橙红、骷髅 #AEADAE 灰白、
  烈焰人 #D2A228 金、潜影贝 #97678C 紫。
  暗色怪（末影人/凋灵/龙）用 `v = min(0.55, 0.30+0.4*原v)` 抬明度并**保留相对深浅**。
- **灵核色 = 贴图里最鲜艳的常见色**（僵尸的青衬衫 #00ACAC、岩浆怪的暗红 #5C1900…）；
  贴图没有彩色的用人工表 `ACCENT_OVERRIDE`（末影人紫、凋灵灵魂蓝、骷髅骨黄）。
  `contrast_core()` 只在「核与球体 RGB 距离 < 80」时才推暗/推亮一档，
  分得开就**原样保留**。
- 人工表 `PRIMARY_OVERRIDE`：僵尸/巨人（平均值被青衬衫带成青绿）、女巫（被黑袍拉成褐紫）、
  掠夺者/卫道士/唤魔者（原本太暗）、洞穴蜘蛛/岩浆怪（原本太暗）。
- **画法 = 硬像素分层**：4 档明暗（`TIERS` + `LAM_TIERS` + 兰伯特光照）
  + 最外圈深色描边 + 左上 1~2 点高光 + 中心菱形灵核（亮心 + 本色 + 一圈暗槽衬底）。
  不插值 → 放大后依然是清晰像素块。
- **验收页** `docs/bead_preview.html`：36 格，内嵌 base64 图标（自包含，离线可看），
  放大 76px + 中英文名 + 主色/灵核色号。这是给用户挑图最省事的交付形式，以后沿用。
- 备选画法 `render_bead_texture()`（珠心嵌怪物贴图，`n=10` 缩小 + 圆形裁切）保留在脚本里，
  换风格改 `main()` 一行即可。

### 踩坑
- 用 `%` 拼 HTML 模板时，正文里的 `100%` 会触发 `ValueError: unsupported format character`
  —— 模板里的百分号要写 `%%`。
- 生成对比图时把两个方案放进同一格，忘了每格宽度要按 `2*cellw` 预留，导致 B 压在 A 上。
- 输出缩到 16px 再放大看时，**必须用 `image-rendering: pixelated`**（HTML）或整数倍最近邻，
  否则会误判成"糊"。

- `build/libs/wulingdiguo-0.2.7.jar`（149,047 B），`BUILD SUCCESSFUL in 35s`；
  已解包核对：37 张贴图 / 37 个模型、基模型 36 条 overrides、zombie.png = 16×16。

## 《武灵帝国》0.2.11：灵珠图标背景改为透明（用户口径「每一个灵珠的背景改为透明」）

### 根因：脚本写的 PNG 根本没有 alpha 通道
排查发现生成的 33 张灵珠图 **colortype = 2（RGB）**，而模组原有的 5 张品质图是
**colortype = 6（RGBA）**。原因在 `png_write` / `png_bytes`：
`IHDR` 里硬编码了 `8, 2, ...`，像素也只写 `pixels[:3]` —— **alpha 通道被整个丢掉**，
球体外的 `(0,0,0,0)` 变成不透明的纯黑，进游戏就是每颗灵珠垫一个黑方块。

### 修法
- `png_write` / `png_bytes` 合并成共用的 `_png_blob()`：按「像素是否 4 元组」
  自动选 colortype（6 或 2），4 通道时写完整 RGBA。
- 验收页 `<img>` 加**棋盘格垫底**（4 行 CSS，`linear-gradient` 两段错位 6px），
  否则透明背景下的浅色灵珠（恶魂 #EBEBEB、骷髅 #AEADAE、远古守卫者）在白页面上看不清。
- 总览图 `write_preview` 本来就 `if a == 0: continue` 跳过透明像素，无需改。

### 验证
逐张解析 jar 内 PNG 的 IHDR + 反解 IDAT 查四角 alpha：
**33/33 张都是 colortype 6，四角 alpha 全为 0，异常 0 张。**

### 产物
- `build/libs/wulingdiguo-0.2.11.jar`（147,410 B），`BUILD SUCCESSFUL in 58s`；
  已解包核对：bead PNG 33 张 colortype 全 6、overrides 33 条缺号 [8,23,27]、版本 0.2.11。
- `docs/灵珠系统设计规格.md` 补一条「贴图必须 RGBA、球外 alpha=0」的硬要求。

## 《武灵帝国》0.2.12：灵珠回复量改为「怪物 × 品质」（用户口径「每种怪物的灵珠恢复不同灵力：比如僵尸凡品5%，末影龙极品100%」）

### 旧逻辑 → 新逻辑
旧：回复量只跟品质挂钩（凡5/良6/优7/上9/极10，写死在 Config）。
新：**回复量 = 怪物基准 × 品质倍率**。
- 怪物基准 = 该怪物「凡品」珠的回复量，写在**新生成的 `item/BeadPower.java`** 的 `BASE` 表；
- 品质倍率 凡×1.0 / 良×1.5 / 优×2.0 / 上×3.0 / 极×4.0（Config `restoreMultiplierFan..Ji`）。
- 两个锚点成立：僵尸基准 5 → 凡品 5%；末影龙基准 25 → 极品 100%。

### 表外来源（模组怪）兜底
`BeadPower.fallbackBase(hp)`：20 血 = 5%，每多 1 点血 +1/9，钳制 [3, 25]。
生命值用 `DefaultAttributes.getSupplier(type).getValue(Attributes.MAX_HEALTH)` 取，
**不需要 Level**（工具提示里能直接算）。取不到就退回 `DEFAULT_BASE = 5`。

### ⚠️ 配置键改名（重要）
`restoreFan..restoreJi`（绝对百分比）**已废弃**，换成 `restoreMultiplierFan..Ji`（倍率）。
**故意换新键名**：Forge 的配置文件生成后不跟随代码默认值更新，若沿用旧键，
老玩家配置里的 5/6/7/9/10 会被当成倍率读，一颗凡品珠就回 25%。旧键会被 Forge 忽略。

### 生成器扩展
`tools/gen_bead_textures.py` 现在多了 `MOB_RESTORE`（33 怪基准表）、
`QUALITY_MULT`，除图标/模型/`BeadModels.java` 外**再产出**：
- `src/main/java/com/wuling/empire/item/BeadPower.java`（`Map.ofEntries` 形式，勿手改）
- `docs/bead_power.html`（33 怪 × 5 品质对照验收表）
⚠️ 写 Java 源码模板时注意 **Python `%` 格式化**：文档注释里的 `（%）` 必须写成 `（%%）`，
否则报 `unsupported format character '?' (0xff09)`。

### 产物
- `build/libs/wulingdiguo-0.2.12.jar`（150,139 B），`BUILD SUCCESSFUL in 1m 38s`；
  已解包核对 BeadPower.class 存在且含 BASE 表、Config 只有新键、版本 0.2.12。
- `docs/灵珠系统设计规格.md`：新增 §4.3「回复量：怪物基准 × 品质倍率」+ 配置表更新。

## 《武灵帝国》0.2.13：绿宝石境界突破条件改为「每种怪物灵珠不限品质各 10 个」

### 用户口径（2026-09-26）
「绿宝石的晋升条件改为每种怪物灵珠（不限品质）各十个，除巨人，疣猪兽，幻术师，
远古守卫者、流浪者和监守者」；追问确认 **10 个绿宝石块保留**。
所以新条件 = `ALL_BEADS;10` + `minecraft:emerald_block;10`。

### 新增 `ALL_BEADS` 特殊键
- `ALL_JI_BEADS;N` = 只收极品（旧口径，代码保留兼容，默认配置已不再使用）
- `ALL_BEADS;N`    = **不限品质**，凡品~极品都计数（绿宝石档现在用这个）
- 面板文案：`wuling.require.all_beads`（中：全体怪物灵珠 · 不限品质（%1$d 种 × %2$d 个））

### 来源集合改用「并集」写法（修掉一个潜在漏项）
`allRequiredBeadSources()` 以前只扫**注册表 MONSTER 分类**。
疣猪兽（hoglin）是 Enemy、照样掉灵珠，但分类是 CREATURE，会被漏掉 ——
用户这次点名要排除疣猪兽，正说明他预期它本来在名单里。
现在改为：**注册表 MONSTER 分类 ∪ 本模组出图怪物（`BeadModels.SOURCES` 去掉 `RETIRED`）**，
再减 `NEVER_DROPS` ∪ `EXCLUDED_MOBS` ∪ 新增配置 `BREAKTHROUGH_EXCLUDED_MOBS`。
结果：36 - (蠹虫/恼鬼/末影螨 3) - (巨人/疣猪兽/幻术师/远古守卫者/流浪者/监守者 6) = **27 种**，
需求 27 × 10 = **270 颗**（任意品质）。

### ⚠️ 缴纳池键改为带品质段（重要，防白嫖）
`bead|<来源>` → **`bead|<来源>|<品质>`**。
不限品质后一次提交可能同时缴进凡品和极品，若仍共用一个键，
退还时就只能一律按极品发（`refundAll` 原来写死 `SpiritQuality.JI`）＝玩家拿凡品换极品。
现在 `takeBeads()` 返回 `Map<SpiritQuality,Integer>`，分品质入账；`refundAll` 按原品质重建堆。
旧存档里没有品质段的键按极品读（兼容）。
